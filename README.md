# AI-Powered Email Template Generator

Backend microservice for **Indus Net Technologies Assignment 2**.

The service accepts a small set of fields — `purpose`, `recipient_name`, and `tone` — and uses the **Groq API** to generate a short, customer-friendly email template.

## Assignment Requirements Covered

- Express.js backend
- POST API with `{ purpose, recipient_name, tone }`
- Groq AI integration
- Modular controller/service/routes structure
- Environment variable for the API key
- Short customer-friendly email generation
- Prompt design documented in the source code and below
- Simple AI response-time measurement
- README with setup and API example
- Postman collection included

## Prerequisites

- Node.js 18 or newer
- npm
- A Groq API key

Groq's official JavaScript SDK is installed as `groq-sdk`, and the API key is read from `GROQ_API_KEY`.

## 1. Install

Open a terminal in the project folder:

```bash
npm install
```

## 2. Configure the API key

Create a `.env` file by copying `.env.example`.

Windows CMD:

```cmd
copy .env.example .env
```

PowerShell:

```powershell
Copy-Item .env.example .env
```

Then open `.env` and set:

```env
GROQ_API_KEY=your_real_groq_api_key
PORT=3000
GROQ_MODEL=openai/gpt-oss-20b
```

**Never commit `.env` or your real API key to GitHub.** The `.gitignore` already excludes `.env`.

## 3. Start the server

Normal mode:

```bash
npm start
```

Development mode:

```bash
npm run dev
```

You should see:

```text
Server running at http://localhost:3000
```

## 4. Test the health endpoint

```text
http://localhost:3000/health
```

Expected response:

```json
{
  "success": true,
  "service": "AI-Powered Email Template Generator",
  "status": "healthy",
  "timestamp": "..."
```

## 5. Test the AI endpoint with Postman

Import:

```text
postman/Assignment-2.postman_collection.json
```

Run **Generate Email - Complaint**.

Request:

```http
POST http://localhost:3000/api/generate-email
Content-Type: application/json
```

Body:

```json
{
  "purpose": "Respond to a customer complaint about a delayed order",
  "recipient_name": "Rahul",
  "tone": "empathetic and professional"
}
```

Example response shape:

```json
{
  "success": true,
  "data": {
    "purpose": "Respond to a customer complaint about a delayed order",
    "recipient_name": "Rahul",
    "tone": "empathetic and professional",
    "subject": "Update on Your Order",
    "body": "Dear Rahul,\n\nThank you for reaching out...",
    "model": "openai/gpt-oss-20b",
    "response_time_ms": 842
  }
}
```

The exact generated email and response time will vary because the response is generated by the AI model.

## How the AI prompt was designed

The prompt is deliberately constrained so the model:

1. Understands the business purpose.
2. Uses the recipient's name.
3. Follows the requested tone.
4. Produces a short, customer-friendly email.
5. Does not invent missing facts.
6. Returns only `subject` and `body` as JSON.

This makes the AI output easier for a backend service to consume than an unrestricted paragraph.

## Response-time logging

The service starts a timer immediately before the Groq request and calculates:

```text
response_time_ms = end_time - start_time
```

The server console prints a log similar to:

```text
[AI] model=openai/gpt-oss-20b response_time_ms=842 timestamp=2026-09-29T...
```

The same value is returned in the API response as `response_time_ms`.

## Error handling

The API handles:

- Missing required fields → `400`
- Missing Groq API key → `500`
- Empty AI response → `502`
- Unknown route → `404`
- Unexpected server/AI errors → `500`
